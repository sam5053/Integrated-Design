## 2. 参与者与使用入口

| 参与者 | 说明 | 使用入口 |
| --- | --- | --- |
| 个人贷款用户（贷款人） | 申请并偿还贷款的实名个人用户，关注申请进度、审批结果、还款金额与个人信息安全 | APP、网页端 |
| 风控审核人员（审核员） | 负责查询贷款人信息、查看模型评估结果并给出人工审批结论 | 网页端 |
| 业务人员 | 负责结清环节的抵押凭证或抵押物结算办理（UC-08） | 网页端 |
| 外部服务 | 实名认证服务、支付服务、短信或消息通知服务、第三方数据源、风控模型服务 | 由系统调用 |

## 3. 全局约束与业务规则

| 编号 | 规则 |
| --- | --- |
| GR-1 | 贷款人账户必须与实名认证信息和贷款业务绑定，未完成实名认证的账户不能发起贷款申请。 |
| GR-2 | 采集和使用个人信息应遵循最小必要原则，采集前展示用途并取得用户授权，不得要求授权范围之外的数据。 |
| GR-3 | 身份证号、银行卡号、联系方式等敏感字段在界面默认以掩码显示，查看完整信息按角色权限控制并记入审计日志。 |
| GR-4 | 注册、登录、认证、申请、审批、放款、还款等关键操作均需留痕，记录操作人、时间与结果。 |
| GR-5 | 贷款进度节点与顺序全系统统一，依次为：提交身份认证资料 → 提交贷款申请 → 身份资料核验与评估 → 签订贷款合同 → 贷款发放 → 贷中 → 贷款完成。 |
| GR-6 | 同一用户存在未完成的同类申请时，系统提示已有申请及其状态，避免重复提交。 |

## 4. 用例详述

### 4.1 贷款人（贷前）

#### UC-01 注册账户

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户、审核人员；短信或验证码服务 |
| 目标 | 建立可用于登录的账户，并将账户与手机号绑定 |
| 触发事件 | 用户在登录页点击【注册】 |
| 前置条件 | 已打开 APP 或网页端；验证码通道可用；手机号未被注册 |
| 后置条件 | 账户创建成功并处于未实名状态，可正常登录；贷款人核心业务功能仍受实名约束 |
| 涉及界面 | 注册页 |
| 关联用例 | UC-02、UC-03 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 用户填写手机号与昵称。<br>2. 用户设置账号密码，系统校验密码强度。<br>3. 系统发送验证码，用户完成校验。<br>4. 用户阅读并同意用户协议与隐私政策。<br>5. 系统创建账户，保存手机号、昵称、密码摘要与注册时间。<br>6. 系统提示注册成功并进入登录页。 |
| 备选事件流 | A1. 手机号已注册时，提示改用登录或找回密码。<br>A2. 验证码错误或过期时，允许重新获取，并对获取频率做限制。<br>A3. 密码强度不足时，提示密码规则并保留已填内容。<br>A4. 用户未同意协议时，阻止提交。 |
| 异常事件流 | E1. 验证码通道不可用时，提示稍后重试。<br>E2. 注册接口失败时，提示重试且不产生半成品账户。 |
| 业务规则 | 一个手机号对应一个账户；审核人员账户的开通方式**待确认**（是否允许自助注册）。 |

#### UC-02 登录与身份分流

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户、审核人员 |
| 目标 | 校验账号身份，并把用户送入与其角色相符的功能界面 |
| 触发事件 | 用户在登录页输入账号后选择登录入口 |
| 前置条件 | 账户已注册；账号未被锁定 |
| 后置条件 | 建立登录会话，会话中保存用户标识与角色；记录登录日志 |
| 涉及界面 | 登录页、前台首页、后台首页 |
| 关联用例 | UC-01、UC-03、UC-10 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 用户输入账号密码，必要时输入验证码。<br>2. 用户点击【贷款人登录】或【审核员登录】。<br>3. 系统校验账号、密码与所选角色是否匹配。<br>4. 个人贷款用户进入前台首页，审核人员进入后台首页。<br>5. 系统按角色显示后续可用功能。<br>6. 系统记录登录时间、终端与结果。 |
| 备选事件流 | A1. 所选角色与账号身份不符时，拒绝登录并提示选择正确入口。<br>A2. 贷款人账号尚未实名时，允许登录但引导完成实名认证，贷款申请入口保持不可用。<br>A3. 同一账号连续多次登录失败时，短时间内限制登录尝试。 |
| 异常事件流 | E1. 会话过期时，要求重新登录并保留未提交的表单内容（如可保存）。 |
| 业务规则 | 前台与后台界面按角色隔离，界面上不出现超出角色的功能入口。 |

#### UC-03 实名认证与银行卡绑定

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户；实名认证服务 |
| 目标 | 核验用户真实身份，把身份信息与银行卡绑定到贷款人账户 |
| 触发事件 | 用户在个人中心选择【实名认证】 |
| 前置条件 | 用户已登录；账户未完成实名认证；实名认证服务可用 |
| 后置条件 | 账户状态置为已实名；身份信息与账户绑定；贷款申请、合同签订与还款均在该实名账户下进行 |
| 涉及界面 | 实名认证页 |
| 关联用例 | UC-01、UC-04 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 用户填写真实姓名、身份证号。<br>2. 用户添加银行卡，可添加多张并指定默认卡。<br>3. 页面展示信息用途说明，用户阅读并同意授权。<br>4. 用户提交认证。<br>5. 系统调用实名认证服务，核验姓名与证件号的一致性，并校验银行卡与本人身份的关系。<br>6. 系统保存认证状态、认证时间与授权记录。<br>7. 页面显示认证结果，账户与身份信息完成绑定。 |
| 备选事件流 | A1. 认证未通过时，说明失败原因（如姓名与证件号不一致、证件过期、银行卡非本人），允许修改资料后重新提交。<br>A2. 同一证件已被其他账户认证时，拒绝绑定并提示。<br>A3. 用户不同意必要授权时，停止采集授权范围之外的数据，并提示无法进入需要认证的业务环节。 |
| 异常事件流 | E1. 实名认证服务超时或不可用时，保留已填信息、标记为待确认并允许重试。 |
| 业务规则 | 银行卡支持多张，任一时刻有且仅有一张默认卡；证件号与银行卡号在界面默认掩码显示（GR-3）。 |

#### UC-04 申请贷款

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户 |
| 目标 | 在实名账户下提交贷款申请，并明确本次的额度、期限与还款安排 |
| 触发事件 | 用户点击【申请贷款】 |
| 前置条件 | 用户已登录且已完成实名认证；贷款产品处于可申请状态 |
| 后置条件 | 生成申请单号，申请状态置为「待风控评估」，进入身份资料核验与评估环节；用户可查询进度 |
| 涉及界面 | 贷款申请页 |
| 关联用例 | UC-03、UC-06；提交后进入系统内部用例《多数据源融合与风险评估》 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 页面展示可申请的贷款产品及额度范围、可选期限、利率或费用说明。<br>2. 用户选择贷款产品，填写申请额度、贷款期限与借款用途等必要信息。<br>3. 页面实时展示申请额度、预期贷款利息与还款节奏，包括还款方式、每期应还金额和还款日安排。<br>4. 系统校验必填项、取值范围与申请资格。<br>5. 页面展示本次需要采集的数据类别及用途，用户确认必要授权。<br>6. 用户提交申请。<br>7. 系统生成申请单号，保存申请快照与试算结果，向用户返回提交结果。 |
| 备选事件流 | A1. 用户未完成实名认证时，申请入口不可用并提示先完成实名认证。<br>A2. 必填字段缺失或格式不正确时，定位到具体字段并阻止提交。<br>A3. 申请额度超出可申请范围时，提示可申请区间。<br>A4. 同一用户存在未完成的同类申请时，提示已有申请及其状态（GR-6）。 |
| 异常事件流 | E1. 提交失败时，提示重试且不生成重复申请单（同一申请幂等）。 |
| 业务规则 | 申请单号全局唯一；申请快照保留提交时的额度、期限、用途与试算结果，供后续审批与合同比对。 |

#### UC-05 签订贷款合同

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户 |
| 目标 | 以电子合同形式完成借款协议的确认与签署，使贷款进入发放环节 |
| 触发事件 | 申请审批通过后，用户进入【待签订合同】 |
| 前置条件 | 申请已通过审核并生成合同文本；合同版本与审批结果一致 |
| 后置条件 | 保存签署记录（签署时间、合同版本、签署方式），合同状态置为已签署，进入贷款发放 |
| 涉及界面 | 电子合同签订页 |
| 关联用例 | UC-04、UC-06 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 用户打开合同页，阅读电子版合同或协议全文。<br>2. 页面展示关键条款摘要，包括授信额度、期限、利率或费用、还款方式、逾期处理和个人信息使用范围。<br>3. 用户确认条款并完成签字盖章手续。<br>4. 系统校验合同版本与审批结果一致。<br>5. 系统保存签署记录并更新合同状态。 |
| 备选事件流 | A1. 用户未完成签署时，流程停留在本环节，不允许进入放款。<br>A2. 用户未确认已阅读即点击签署时，提示需先确认阅读关键条款。<br>A3. 合同版本与审批结果不一致时，提示并要求重新确认，本次签署作废。 |
| 异常事件流 | E1. 签署结果保存失败时，提示重新提交，且不置为已签署。 |
| 业务规则 | 签字盖章方式可采用页面手写签名或上传签名图片，具体方案在开发阶段确定；本阶段只实现合同展示与签署界面，**待确认**，指纹等生物特征不作为本阶段方案。 |

#### UC-06 查看贷款进度

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户 |
| 目标 | 让用户了解申请当前所处环节、已完成环节的处理结果与后续待办 |
| 触发事件 | 用户进入【我的贷款】 |
| 前置条件 | 用户已登录 |
| 后置条件 | 无（查询类用例），进度查询行为计入用户操作记录 |
| 涉及界面 | 贷款进度查询页 |
| 关联用例 | UC-04、UC-05、UC-07、UC-08 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 页面按环节展示当前进度：提交身份认证资料 → 提交贷款申请 → 身份资料核验与评估 → 签订贷款合同 → 贷款发放 → 贷中 → 贷款完成。<br>2. 页面标注各环节的完成时间与处理结果。<br>3. 页面展示审批结论、授信额度、期限与还款计划。 |
| 备选事件流 | A1. 审批未通过时，展示结论及主要影响因素。<br>A2. 材料不足被退回时，列出需要补充的项目和重新提交入口。<br>A3. 无任何申请记录时，提示尚未申请并引导至申请入口。 |
| 异常事件流 | E1. 状态更新延迟时，展示最近一次更新时间，避免显示过期状态。 |
| 业务规则 | 进度节点名称与顺序全系统统一（GR-5），APP 与网页端展示一致。 |

### 4.2 贷款人（贷中与贷后）

#### UC-07 还款与还款进度查询

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户；支付服务 |
| 目标 | 用户查询还款计划并完成还款，系统准确更新账单与贷款余额 |
| 触发事件 | 用户进入【我的贷款—还款】 |
| 前置条件 | 用户存在已放款且未结清的贷款；账单与支付服务可用 |
| 后置条件 | 还款流水、账单状态与贷款余额保持一致；用户可查询历史还款记录 |
| 涉及界面 | 还款与结清页 |
| 关联用例 | UC-06、UC-08 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 用户查看应还本金、利息、费用、还款日与已还金额。<br>2. 页面按期列出账单与历史还款记录，展示还款进度。<br>3. 用户选择当期账单并提交支付。<br>4. 系统调用支付服务并接收支付结果。<br>5. 支付成功后，系统更新账单状态与贷款余额，展示还款结果。 |
| 备选事件流 | A1. 支付失败时，不将账单标记为已还，提示失败原因并允许重试。<br>A2. 临近还款日时，页面显示还款提醒。<br>A3. 用户选择提前还款时，按拓展功能处理，功能未上线前页面给出说明。 |
| 异常事件流 | E1. 支付结果未明确（超时或掉单）时，订单置为处理中，由对账任务确认真实结果，禁止重复扣款。 |
| 业务规则 | 账单展示应能区分本金、利息与费用；已结清账单不可重复支付。 |

#### UC-08 结清与抵押物处理

| 项目 | 说明 |
| --- | --- |
| 参与者 | 个人贷款用户、业务人员 |
| 目标 | 全部账单还清后完成贷款结清，并办理抵押凭证或抵押物的结算 |
| 触发事件 | 最后一期账单还款成功 |
| 前置条件 | 该笔贷款全部账单已结清 |
| 后置条件 | 贷款状态置为「贷款完成」，结清证明与结算记录归档 |
| 涉及界面 | 还款与结清页、业务端处理界面 |
| 关联用例 | UC-07 |

| 事件流 | 内容 |
| --- | --- |

| 业务规则 | 结清与抵押物结算的判定条件、材料清单以业务规则为准，本阶段先实现状态展示与提示。 |

#### UC-11 待审核贷款人工审批

| 项目 | 说明 |
| --- | --- |
| 参与者 | 风控审核人员 |
| 目标 | 结合模型评估结果与人工判断给出审批结论，推动申请进入合同与放款环节 |
| 触发事件 | 申请完成风险评估后进入待审核队列，审核人员打开待审核列表 |
| 前置条件 | 申请已完成身份资料核验与风险评估；审核人员已登录并具有该申请的处理权限 |
| 后置条件 | 保存审批结论、审核人员、处理时间与人工意见；批准时生成授信额度、期限与还款计划并进入签订合同环节，拒绝时向用户展示结果说明 |
| 涉及界面 | 待审核贷款与人工审批页 |
| 关联用例 | UC-10、UC-12、UC-05 |

| 事件流 | 内容 |
| --- | --- |
| 基本事件流 | 1. 审核人员进入待审核列表，选择一条申请。<br>2. 页面展示贷款信息（申请额度、贷款期限、借款用途）。<br>3. 页面展示贷款人信息与实名认证结果。<br>4. 页面展示模型风险评估结果，包括信用评分、风险等级、规则命中原因与处理建议。<br>5. 审核人员核对材料后选择人工审批结果（批准或拒绝），并填写人工意见。<br>6. 审核人员提交审批结论。<br>7. 系统保存审批记录并更新申请状态；批准时生成授信额度、期限与还款计划，并通知用户签署合同。 |
| 备选事件流 | A1. 人工意见为空或未查看风险解释时，不允许提交。<br>A2. 申请材料不足时，审核人员退回补充资料，用户补充后重新进入评估或复核流程。<br>A3. 审批拒绝时，保存拒绝原因与主要影响因素，并向用户展示合适的结果说明。<br>A4. 同一申请被多人同时处理时，后提交者收到冲突提示，需刷新后重新处理。 |
| 异常事件流 | E1. 审批结果保存失败时，提示重试，且不产生部分生效的审批状态。 |
| 业务规则 | 审批结论只能为批准或拒绝（材料不足时先退回补充资料）；审批记录不可删除，只可追加修订记录。 |

## 5. 用例之间的关系
